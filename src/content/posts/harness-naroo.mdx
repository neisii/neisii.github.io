[harness-naroo](https://github.com/neisii/harness-naroo)는 Claude Code에 설치하는 플러그인이다. 규칙 문서와 스킬로 되어 있고, 설치하면 Claude가 작업 하나를 성공시키는 데서 멈추지 않고 그 결과가 시스템 전체와 맞물리는지 확인하는 절차를 지킨다. 사람이 결정할 지점에서는 멈추고 묻는다. 라이선스는 Apache-2.0이고, Claude Code 안에서 두 줄로 설치한다.

```sh
/plugin marketplace add neisii/harness-naroo
/plugin install ai-dlc-harness@harness-naroo
```

## 왜 만들었나

2026년 공공 조달 차세대 구축 사업에서 AI 세션 여러 개에 역할을 나눠 화면을 개발했다. 그때 같은 일을 계속 겪었다.

- AI가 "완료, 테스트 통과"라고 보고한 작업도 다른 작업과 합치면 깨졌다.
- AI가 묻지도 않고 커밋하거나 파일을 지웠다.
- 세션이 늘수록 모든 승인 요청이 나 한 명에게 몰렸다.

일이 생길 때마다 규칙을 하나씩 더했고, 그 규칙을 하네스로 정리했다. 그 사업에서 하네스는 화면 34개를 일정보다 한 달가량 앞당겨 납품하는 데 쓰였고, 규칙 13개·스킬 27개·도구 31개까지 늘었다. 공개판은 그중 사업에 묶이지 않은 핵심을 익명화해 추린 것이다.

## 작업 하나가 아니라 합친 전체

에이전트 도구 대부분은 "이 작업이 성공했나"를 본다. 이 하네스는 "이 작업이 전체를 깨뜨리지 않았나"를 본다.

출시 전에 공개 저장소 [gate3-trial](https://github.com/neisii/gate3-trial)에서 시험한 장면이 이 차이를 잘 보여 준다. 작은 주문 처리 시스템을 만들면서 세 기능(주문 부분취소, 일별 매출 집계, 상태별 알림 문구)을 AI 세션 셋이 동시에 만들었다.

- 뼈대 작업의 청사진(작업 계획)에 "부분취소 기능이 매출 집계·알림 문구에 영향을 준다"는 메모가 있었고, 세 기능을 시작하기 전에 사람이 정할 일로 올라왔다.
- 부분취소 기능을 합치기 전에, 작업 대화를 물려받지 않은 다른 AI가 합친 코드를 실제로 실행해 봤다. 결제한 주문 두 건(합계 6,000원) 가운데 한 건을 부분취소하자, 남은 금액 3,000원까지 매출에서 빠져 합계가 4,000원이 아니라 1,000원이 됐다.
- 이때 각 기능의 테스트는 모두 통과한 상태였다. 작업 하나씩 보면 다 성공이었다.

이 숫자를 근거로 매출 쪽 후속 작업이 생겼고, 그 작업은 "모든 주문 상태가 매출에 넣을지 뺄지 정해져 있다"는 테스트를 더했다. 마지막에는 모든 작업을 합친 결과를 병합 전에 미리 만들어 테스트 90건이 통과하는 것을 확인했다.

## 하네스가 하는 일

- **사람 게이트:** 청사진을 사람이 승인하기 전에는 구현하지 않고, 커밋 계획을 승인하기 전에는 커밋하지 않는다.
- **확인한 것만 확인했다고 쓴다:** "통과"라는 말 대신 실행한 명령과 출력을 인용하고, 확인하지 못한 것은 못 했다고 적는다.
- **새 맥락 재검증:** 작업한 AI와 같은 대화를 가진 검증자는 같은 것을 놓친다. 그래서 커밋 전에 그 대화를 물려받지 않은 AI가 한 번 더 본다.
- **자기 채점 금지:** 결과를 만든 세션은 그 결과를 승인하지 않는다.
- **가역성 판정:** 규칙에 정해 두지 않은 상황에서 "혼자 해도 되나, 멈추고 물어야 하나"를 기준 4개로 판정한다. 되돌릴 수 없는 일, 요구가 모호한 일, 사람이 정할 업무 결정은 다른 기준이 모두 괜찮아도 멈춘다. 할인율을 15%로 바꾸는 코드는 되돌릴 수 있고 요구도 명확하지만, 할인율은 사람이 정할 일이라 AI가 혼자 정하지 않는다.

## 여러 세션으로 나눠 쓰기

0.2.0에서는 작업을 Claude Code 세션 여러 개에 나눠 쓰는 구성을 넣었다. 사람이 결정하고, 게이트웨이 세션이 사람과 다른 세션 사이에서 메시지를 전하며 진행을 지켜보고, 실무자 세션이 구현한다.

시험하면서 예상과 다른 것도 배웠다. 사람이 내린 결정은 약 17번이었는데, 명령마다 실행해도 되는지 묻는 권한 창이 약 68번 떴다. 그중 사람이 꼭 봐야 했던 것은 약 14번뿐이었다. 그래서 권한 모드 기본값을 auto로 바꾸고, 꼭 막아야 할 것(main 직접 push, 기밀 유출, 업무 결정)은 브랜치 보호와 게이트로 막는 쪽으로 안내서를 고쳤다.

0.2.1에서는 세션이 권한 창에 멈춘 것인지, 턴을 끝내고 답을 기다리는 것인지를 구분하는 기능을 더했다. 시험할 때 둘을 구분하지 못해, 게이트웨이가 실무자의 대화 기록을 직접 읽어야 했던 문제다.

## 만들면서 배운 것

- **재검증은 내 실수도 잡았다.** 0.2.1 작업 중에 상태 판정을 둘로 나누면서, 이미 프로세스가 끝난 세션에 "메시지를 보내면 깨어난다"고 잘못 안내하는 버그를 만들었다. 새 맥락의 검증자가 실제 세션으로 재현해 잡았다.
- **출시 전에 공개 문서를 전수 점검했다.** 규칙과 문서가 서로 다르게 말하는 곳, 시험 결과가 반영되지 않은 곳이 생각보다 많았다. 하네스가 코드에 요구하는 "전체가 맞물리는가"를 문서에도 똑같이 적용해야 했다.
- **공식 플러그인 디렉터리에는 올리지 않는다.** 디렉터리는 인증된 조직이 아니면 플러그인 안의 스크립트 파일을 받지 않는다. 이 하네스는 판정과 점검을 스크립트로 정확하게 하는 것이 핵심이라, 직접 설치로만 배포하기로 했다.

## 시작하려면

처음이라면 [상황 지도](https://github.com/neisii/harness-naroo/blob/main/docs/guide/00-상황지도.md)부터 보면 된다. "묻지도 않고 커밋했다", "하나하나는 성공했는데 합치니 깨졌다"처럼 AI를 쓰다 겪는 문제로 찾는 안내서다. 5분 안에 실행해 볼 수 있는 예제는 [QUICKSTART](https://github.com/neisii/harness-naroo/blob/main/QUICKSTART.md)에 있고, 플러그인을 설치하지 않아도 Python 3만 있으면 된다.

아직 실전 시험 표본이 작고, 규칙 정본은 한국어이며, Claude Code에서만 쓸 수 있다. 다음 판(0.3.0)에서는 여러 작업을 합쳐 내보내는 흐름(통합·릴리스)을 다룰 계획이다.
